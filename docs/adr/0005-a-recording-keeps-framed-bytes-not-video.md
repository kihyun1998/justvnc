# A Recording keeps the framed bytes that crossed, not video

A session is recorded as the RFB bytes that crossed after the handshake, one framed message per entry with its direction and a time the host supplies, in a crate of its own (`justvnc-record`). Replay feeds those bytes back through the client role's decoding, so a Recording costs the recorder no decoding and no encoder, and frames, images or video can be produced from it later by a separate tool. Recording straight to video was rejected because it puts an encoder dependency and decoding work into the program that sits between untrusted peers, and because bytes can always become video later while video cannot become bytes again. The handshake is never recorded, so a Recording holds no password, challenge or response; it starts at ServerInit. What is recorded is the Target's messages to the Viewer and the Viewer's input, so an audit shows both what was seen and what was typed (maintainer's call), which means a Recording holds whatever the user typed, passwords included, and must be protected like one.
